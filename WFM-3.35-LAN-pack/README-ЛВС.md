# План-табель служебной деятельности · WFM 3.35 — пакет для локальной сети

Всё необходимое для развёртывания БЕЗ интернета: приложение, офлайн-сборка, сервер
синхронизации, OCR-ассеты и зависимость `ws` уже внутри архива.

## Состав
| Путь | Назначение |
|---|---|
| `План-табель-WFM-3.35.html` | основная сборка (библиотеки грузит с сервера ЛВС или деградирует до CSV) |
| `План-табель-WFM-3.35-offline.html` | полностью автономная (12,8 МБ): библиотеки, WASM, OCR-модели внутри; работает с сетевого диска по file:// |
| `server/sync-server.mjs` | сервер ЛВС: HTTP-раздача, WS-синхронизация канона, операционный протокол, аутентификация и deny-права, чат, сигналы, /admin, /status, /health, /metrics, реплика, бэкап-крон, SQLite-канон с шифрованием AES-256-GCM (3.30), SSO-прокси и REST-обмен «1С»/СКУД (3.34), справочник кодов Т-13, журнал обмена с ретраем (3.35) |
| `server/ocr/` | Tesseract.js 7 + WASM-ядро + модели rus/eng для раздачи `/ocr/*` |
| `server/make-user.mjs` | создание пользователей (логин, PIN-hash, роль, emp, allow/deny) |
| `server/install-service.sh`, `server/plan-tabel.service` | установка как службы systemd (Restart=always) |
| `node_modules/` | все runtime-зависимости сервера (ws, sql.js, tesseract.js + ядро) — npm не нужен |
| `Dockerfile`, `docker-compose.yml` | контейнерный контур: том /app/data, HEALTHCHECK, реплика через profile ha |

## Быстрый старт (одна машина-сервер)
1. Распакуйте архив в каталог, например `/opt/plan-tabel` (или любой на Windows/Linux).
2. `node server/sync-server.mjs` — сервер напечатает LAN-адреса `http://192.168.x.x:8787/`.
3. Рабочие места открывают этот адрес: приложение раздаётся с сервера и само подключается
   к синхронизации того же origin (реконнект автоматический).
4. Проверка: `curl http://localhost:8787/health` и `/status`; панель — `/admin`.

## Аутентификация и права
`node server/make-user.mjs ivanov 1234 editor users.json e12 --deny=chat`
затем `PT_USERS_FILE=users.json node server/sync-server.mjs`.
Роли: admin, hr, editor, tab (planOnly), viewer. deny применяется сервером: edit (публикация
и ops), staff/import (разделы канона), chat, sign, admin. Пользователей можно вести и из /admin.

## Служба systemd (автоподнятие после сбоев и перезагрузок)
`sudo bash server/install-service.sh 8787 /opt/plan-tabel`
Окружение редактируется в `/opt/plan-tabel/server/plan-tabel.env`
(PT_USERS_FILE, PT_QUOTA, PT_REPLICA_OF, PT_DIGEST_CRON, PT_BACKUP_CRON и др.).

## Резервный узел
На второй машине: `PT_REPLICA_OF=ws://primary:8787 node server/sync-server.mjs` —
тянет канон на чтение; при аварии первичного в /admin реплики — «Повысить до primary».

## Полностью автономные рабочие места (без сервера)
Разложите `…-offline.html` по сетевому диску: открытие по file:// поддерживает и OCR сканов,
и печать, и экспорт XLSX/DOCX (всё внутри файла). Обмен — через общую папку или сервер ЛВС.

## Возможности клиента (3.32–3.33)
OLAP-куб (9 измерений × 9 мер), виджеты виз-стандарта: дивергентный план-факт, теплокарта
с маргинальными сводками, корреляционная матрица, точечная форма, полосы P25–P75, лог-шкала,
предагрегаты «год → квартал → месяц»; НСИ-реестры: виджеты, экраны, отчёты, интерактивные
отчёты, план коммуникаций, меры успеха; телеметрия и канал обратной связи.

## Резервные копии канона
По расписанию: `PT_BACKUP_CRON='02:00,14:00'` или интервал `PT_BACKUP_EVERY_MIN=360`;
каталог `server/backups`, хранение `PT_BACKUP_KEEP=14`. Список, создание и восстановление —
в /admin («Резервные копии канона»).

## Серверный OCR (3.31)
`POST /api/v1/ocr` с `{image: base64, lang}` — распознавание скана на сервере
(Tesseract в Node, ассеты `server/ocr`); приложение по HTTP само пробует сервер раньше
встроенного движка. Требует SQLite-канон не обязателен, но рекомендуется `PT_DB`.

## SSO-реверс-прокси (3.34)
За nginx/Keycloak/AD FS задайте `PT_SSO_HEADER=X-Forwarded-User` (опционально
`PT_SSO_NAME_HEADER`): сервер доверяет заголовку прокси и пускает по WS и REST без PIN.
Новые логины авторегистрируются с ролью `PT_SSO_ROLE=viewer`
(`PT_SSO_PROVISION=0` — только существующие учётки). Флаг виден в /health (`"sso": true`).

## Обмен «1С» и СКУД (3.34)
`GET /api/v1/tabel?y=2026&m=10&dept=d1&fmt=csv` — выгрузка табеля (Т-13: табельный, ФИО,
дата, день недели, код план/факт): JSON по умолчанию, CSV с «;» и BOM для Excel/1С.
`POST /api/v1/tabel {y,m,rows:[{tab|name|eid,d,code,layer}]}` — импорт плана/факта через
операционный протокол: серверные права и комплаенс закрытых периодов действуют.
`POST /api/v1/skud {rows:[{tab|name|eid,ts}],code,minEvents,minHours}` — события прохода
агрегируются в дни факта (по умолчанию ≥2 событий и ≥4 ч, код дня «Я»).

## Коннектор «1С» и веб-панель обмена (3.35)
**Сопоставление кодов Т-13**: карточка «Обмен «1С»» в приложении (раздел «Данные») ведёт
справочник «код формы Т-13 → код причины» (автозаполнение из кодов и алиасов, валидация:
неизвестные локальные коды, дубли, непокрытые коды, неоднозначность обратного сопоставления;
хранение в каноне). `PUT /api/v1/xchg/map {items:[{t13,local,note}]}` — общий справочник
сервера (права staff/admin; `local:""` — снять сопоставление), `GET /api/v1/xchg/map` —
чтение (авто-правила по канону + переопределения). Параметр `map=1c` в
`GET /api/v1/tabel?y=&m=&map=1c` конвертирует локальные коды в коды Т-13 при выгрузке,
а `POST /api/v1/tabel {map:"1c"}` — обратно при импорте. Неизвестные коды не отбрасываются:
проходят как есть и попадают в предупреждения журнала обмена.
**Журнал обмена (веб-панель)**: сервер пишет в `PT_XCHG_FILE` (до `PT_XCHG_MAX=300` записей)
все выгрузки и импорты: tabel-get / tabel-post / skud-post / ocr-post / map-put — статус
(ok/warn/error), счётчики (строки, применено, неизвестные, предупреждения), автор, время;
для неудачных импортов сохраняется исходный запрос (до 200 КБ).
`GET /api/v1/xchg/log?limit=&kind=&status=` — просмотр; `POST /api/v1/xchg/retry {id}` —
повтор операции с сохранённым запросом (права import; серверные права и комплаенс закрытых
периодов действуют и при повторе). Журнал виден в карточке «Журнал обмена» приложения
(фильтры, CSV, кнопка «↻ Повтор»), в панели `/admin` (секция «Обмен «1С» / СКУД») и
транслируется подключённым клиентам по WS (`{type:"xchg"}`) в реальном времени —
ошибки обмена показываются тостом. Метрики Prometheus: `wfm_xchg_total{kind,status}`,
`wfm_xchg_retries_total`, `wfm_xchg_journal_entries`, `wfm_xchg_map_items`.

## Масштаб (3.34)
Проверен нагрузочный профиль: 500 одновременных WS-клиентов (`tests/load-500-334.mjs`),
шторм ops-батчей: p95 ≈ 1 с, RSS сервера ≈ 65 МБ; presence-рассылка троттлируется (1,5 с).

## Docker
`docker compose up -d` — primary на :8787, данные в ./server-data;
`docker compose --profile ha up -d` — плюс реплика на :8788.

## Метрики и журнал
`/metrics` — Prometheus (клиенты, канон, RTT, публикации, операции, отказы, бэкапы,
журнал обмена `wfm_xchg_*` — 3.35); журнал сервера — `server/plan-tabel-server-audit.jsonl`
(ротация), выгрузка CSV из /admin; журнал обмена — `server/plan-tabel-xchg.json` (3.35).
